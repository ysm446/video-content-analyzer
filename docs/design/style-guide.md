# UI スタイルガイド

最終更新: 2026-08-11
初版: 2026-07-03（`ui-design-guidelines.md` として作成 → 2026-08-11 に本ファイルへ統合）

対象:
- `frontend/css/common.css` … デザイントークンと汎用コンポーネント（他アプリと共有する基準）
- `frontend/pages/app.html` の `<style>` … このアプリ固有のレイアウト・部品

**このファイルがアプリの見た目に関する唯一の基準ドキュメント。**
UI を変更するときは、実装前に該当セクションを読み、実装後に §14 のチェックリストを通すこと。
ここに書かれていないパターンを新設したくなったら、既存の部品で代替できないかをまず検討し、
どうしても必要ならこのファイルに追記してから実装する（実装だけ先行させない）。

---

## 1. デザイン原則

コンセプトは **シンプルかつスタイリッシュ**。

1. **ダーク基調のフラットデザイン。** 階層は「背景色の段差＋1px の境界線」だけで表す
2. **色はほぼモノトーン。** アクセント（青）は「操作できるもの・進行中のもの・選択中のもの」だけ
3. **意味のない装飾をしない。** 影・グラデーション・アニメーションは意味があるときだけ
4. **同じ意味には同じ見た目。** 状態ドット・バッジ・メニューはどの画面でも同じ規則で描く
5. **情報密度は高め、けれど詰め込まない。** 動画プレイヤーが主役なので、周辺 UI は静かに保つ

## 2. カラートークン

`common.css` の `:root` に定義。**色はトークン経由で使い、生の HEX を書かない**（例外は §2-3）。

### 2-1. トークン一覧

| トークン | 値 | 用途 |
|---|---|---|
| `--bg` | `#0d0d0d` | 最背面（ページ背景・入力欄の地・動画背景まわり） |
| `--surface` | `#1a1a1a` | パネル・バー・モーダルの面 |
| `--surface2` | `#252525` | 面の中の面（入力欄・リスト項目・ホバー） |
| `--surface3` | `#343434` | さらに一段明るいホバー面（アイコンボタンのホバー等） |
| `--border` | `#2f2f2f` | すべての境界線（`1px solid`） |
| `--border-strong` | `#454545` | ホバー時の境界線・浮いている要素の枠 |
| `--focus-border` | `#555555` | 入力欄フォーカス時の枠線 |
| `--text` | `#e0e0e0` | 本文 |
| `--text-dim` | `#888888` | 補助テキスト・ラベル・非アクティブ |
| `--accent` | `#4a9eff` | 操作可能・進行中・選択中（青） |
| `--accent-hover` | `#6ab3ff` | アクセントのホバー・リンク |
| `--accent-dim` | `#3a6fb0` | アクセントの暗色（シマー・グラデの端） |
| `--success` | `#4caf50` | 完了・ロード済み・分析済み |
| `--warning` | `#ff9800` | 注意・未保存・ブックマーク |
| `--error` | `#f44336` | 失敗・破壊的操作・中止 |
| `--radius` | `8px` | 基本の角丸 |

### 2-2. 状態色のティントトークン

面（背景）で状態を表すときは、必ず「淡い塗り＋やや濃い枠」のティント形式にする。
生の `rgba()` を書かず、以下のトークンを使う。

| トークン | 用途例 |
|---|---|
| `--accent-tint-bg` / `--accent-tint-border` | 選択中の行・実行中ボタン・アクティブなタブ・チップのホバー |
| `--success-tint-bg` / `--success-tint-border` | ロード済みバッジ |
| `--warning-tint-bg` / `--warning-tint-border` | 保存（未保存の変更あり）ボタン |
| `--error-tint-bg` / `--error-tint-border` | 中止ボタン・破壊的メニュー項目 |

```css
/* ○ 正しい状態面 */
.detail-action-btn.running { background: var(--accent-tint-bg); border-color: var(--accent-tint-border); }
/* × ベタ塗り、× 生 rgba */
.detail-action-btn.running { background: #4a9eff; }
```

### 2-3. 色のルール

- **背景の階層は bg → surface → surface2（→ surface3 はホバーのみ）まで。** それ以上は境界線で区切る
- **アクセントは面積を取らない。** ボタン塗り・ドット・細線・アイコン・テキストなど小さい要素だけ。
  広い面をアクセントで塗る唯一の例外はモデルピル（アプリの主役表示）
- **success / warning / error は意味があるときだけ。** 装飾やカラフルさのために使わない
- 生 HEX を書いてよい例外は次の3つだけ:
  1. `#fff` / `#000`（普遍色。アクセント上の文字色、動画・サムネールの下地）
  2. 字幕表示色（`#d0d0d0` / `#e2e2e2` など。映像の上での可読性を優先する）
  3. 白の極薄オーバーレイ `rgba(255,255,255,.03〜.10)`（タグ／スペックチップの地・微細な区切り）
- 新しい意味の色を足さない。赤は `--error`、橙は `--warning` の1系統に統一する

## 3. タイポグラフィ

- フォント: `'Segoe UI', 'Hiragino Sans', 'Yu Gothic UI', sans-serif`
  - コード: `ui-monospace, Consolas, monospace`
  - 字幕のみ `--subtitle-font`（`'Noto Sans JP','Noto Sans',…`）を使う
- ベース 14px / 行間 1.5
- **サイズスケールは 11 / 12 / 13 / 14 の4段が基本。10px 以下は使わない。**
  表示系（字幕 17 / 19px、ヘッダー見出し 16px）だけ例外
- ウェイトは 400（本文）と 600（見出し・強調）の2つ。500 はボタンのみ
- **セクション見出しは「小さく・薄く・大文字」**:
  `font-size:11〜12px; color:var(--text-dim); text-transform:uppercase; letter-spacing:.06em`
  （`.section-label` / `.modal-section-label` / `.analysis-header` / `.qa-title` / `.pane-tab` 共通）
- 数値（経過秒・時刻・使用率・ビットレート）は `font-variant-numeric: tabular-nums` で桁揃え
- 1行に収めるテキストは `white-space:nowrap; overflow:hidden; text-overflow:ellipsis` ＋ `min-width:0`
  （flex/grid の中では `min-width:0` を忘れると省略が効かない）

既知の逸脱（新規コードで真似しない）: ファイルツリーの `12.5px` / `10.5px`、
ルート履歴パスの `10px`。触るタイミングで 12 / 11px へ寄せる。

## 4. 形状・角丸・境界線

| 半径 | 用途 |
|---|---|
| `4px` | 最小要素（サムネール・インラインコード・中止ボタン） |
| `6px` | リスト項目・メニュー項目・小さな入力欄・タグ／スペックチップ |
| `8px`（`--radius`） | 標準（ボタン・カード・入力欄・メニュー枠・小アイコンボタン） |
| `10–12px` | モーダルパネル（モデル 10px / 設定 12px）・モデルピル・チャット吹き出し |
| `99px` / `999px` | 完全な丸（バッジ・チップ・ドット・スライダー・円形コントロールボタン） |

- 境界線は常に `1px solid var(--border)`。太線・二重線・点線は使わない
  （例外: 空状態のプレースホルダのみ `1px dashed var(--border)`）
- ホバーで枠を強調するときは `--border-strong` に差し替える（太さは変えない）

## 5. 余白・寸法

- 余白は **2px グリッド**。`gap: 3 / 6 / 8 / 10 / 12 / 14`、`padding: 8〜20`
- パネル内側の標準パディングは `12px 14px`、モーダル本文は `14px 16px`

### 定型の高さ

| 要素 | 高さ |
|---|---|
| トップバー（`.sidebar`） | 42px |
| 各ペインのヘッダー行（ファイル一覧・プレイヤー上・分析・チャット） | `min-height:56px` |
| ステータスバー | 28px |
| モデルピル・小ボタン | 32px |
| 円形コントロールボタン（`.ctrl-btn`）・タブボタン | 34px |
| ヘッダー内アイコンボタン（`.pane-header-btn` / `.file-panel-btn`） | 28px |
| 行内の「…」ボタン（`.file-row-more`） | 22px |

**ペインのヘッダーは必ず `min-height:56px` に揃える**（左右のパネルで頭の高さがズレると台無しになる）。

### ボタンのサイズは2種

- 標準 `.btn`: `padding:10px 20px` / `font-size:14px`
- コンパクト: `padding:5〜7px 10〜14px` / `font-size:12px`
  … ツールバー・ペインヘッダー・モーダル内はこちら

## 6. エレベーション（影・重なり）

フラット基調。**通常の UI に影は使わない**（面の差＋境界線で表す）。
影を付けるのは「浮いているもの」だけ。

| 要素 | 影 |
|---|---|
| モーダルパネル | `0 24px 64px rgba(0,0,0,.5)` |
| ドロップダウン／コンテキストメニュー | `0 12px 32px rgba(0,0,0,.34)` |
| ツールチップ・シークプレビュー | `0 6px 24px rgba(0,0,0,.65)` |

- モーダルの背景は **暗転＋ぼかし**: `rgba(0,0,0,.45)` + `backdrop-filter: blur(4px)`
  （`-webkit-backdrop-filter` も併記する）
- `z-index` の段: メニュー `8〜20` / モーダル `500` / 追従ツールチップ・プレビュー `9998〜9999`。
  新しい層を勝手に増やさず、この4段のどれかに載せる

## 7. アイコン

- **Lucide Icons のみ。絵文字は使わない。** `frontend/vendor/` にローカル同梱（オフライン動作のため）
- 動的に DOM を生成したら **必ず `lucide.createIcons()` を呼ぶ**（スクリプト末尾でも呼ぶ）
- 方向性: フラット＋ややデフォルメ。**stroke-width は基本 2.2**

| 文脈 | サイズ | stroke-width |
|---|---|---|
| 既定（本文・ボタン内） | 14px | 2.2 |
| コントロールボタン・モデルピル | 15px | 2.2 |
| ヘッダー内アイコンボタン | 15px | 2.2 |
| メニュー項目・行内バッジ | 12–13px | 2.2 |
| キャレット（開閉・プルダウン） | 12–16px | 2.4 |
| サイドバーの大アイコン | 20px | 2 |
| 空状態の飾り | 34–48px | 1.4–1.6 |

- Lucide に無いアイコン（モデルのイジェクト ⏏ 等）は同じ stroke 流儀のカスタムインライン SVG を作り、
  `class="lucide"` を付けて共通 CSS（サイズ・stroke-width）を適用する。
  `createIcons()` は `<i data-lucide>` のみ置換するのでカスタム SVG はそのまま残る
- **アイコン単独のボタンには必ず `title` を付ける**（ラベルが無いなら説明が要る）

## 8. モーション

- ホバー・色変化は **0.15s**（軽い要素は 0.12s）、押下は `transform: scale(.97〜.99)` + 0.1s
- プログレスバーの伸びは 0.3s ease、システム情報バーは 0.6s ease
- ループアニメーションは「進行中」の表現だけに使う:
  - 状態ドットの点滅 `blink`（1.2s、opacity 1↔.3）
  - モデルピルのシマー `pill-shimmer`（1.4s）とアイコンの `pill-pulse`（1.4s）
- 出現アニメーションは短く控えめに（例: 質問チップの `chip-in` 0.2s、3px の持ち上がりのみ）
- バウンス・パララックス・スライドインなど装飾目的の動きは使わない

## 9. コンポーネント規約

### ボタン
- `.btn-primary`（アクセント塗り・白字）は **1画面に主要操作ひとつだけ**
- それ以外は `.btn-ghost`（`surface2` ＋ `border`）
- 実行中は `--accent-tint-*`、未保存の保存操作は `--warning-tint-*`、
  破壊的操作は `--error-tint-*` のティント形式
- `:disabled` は `opacity:.4〜.45; cursor:not-allowed`（色を変えない）

### アイコンボタン
- 円形（34px・`border-radius:999px`）はプレイヤーのコントロール列だけ
- それ以外の角丸（28px・8px）はヘッダー／パネル用
- 行内の補助操作（`…`）は `opacity:0` → 行ホバーまたはメニュー展開中に `1`

### モデルピル
- アプリで唯一アクセントを広く塗る要素。状態は3つ:
  ロード済み（`accent → accent-hover` のグラデ）/ 未ロード（`.off`・`surface3 → surface2`）/
  ロード中（`.loading`・シマー）

### 状態ドット
- 6–8px の円。**灰＝待機 / 青＋点滅＝実行中 / 緑＝完了 / 赤＝エラー**
- ステータスバー・ステータスログ・モデル一覧・ランタイム一覧で同じ意味づけを守る

### バッジ・チップ
- バッジ: ピル型（`radius:99px`）＋ティント形式（例: ロード済み＝success）
- 質問チップ: ピル型・`surface2`＋`border`、ホバーでアクセントティント
- タグ／スペックチップ: `radius:6px` / 11px / `border:1px solid rgba(255,255,255,.06)` /
  `background:rgba(255,255,255,.03)`。ラベルは `--text-dim`、値は `--text`

### リスト行（ファイルツリー・シーン・ブックマーク）
- 行は `radius:6px`、ホバーは `surface2`、選択中は `--accent-tint-bg` ＋ 文字 `--accent`
- 左からアイコン → サムネール → テキスト（2行まで） → バッジ → `…` の順を守る
- サムネールは `radius:4px`、地は `#000`、`object-fit` は一覧で `cover` / 詳細で `contain`

### メニュー（ドロップダウン／コンテキスト）
- 枠 `surface` ＋ `border` ＋ `radius:8px` ＋ `padding:6px` ＋ メニュー影
- 項目は `padding:7px 10px` / 12px / `radius:6px`、ホバーで `surface2`
- 破壊的項目は `.danger`（`--error`）で最下段
- チェック状態はテキスト頭の 14px 幅のチェック枠で表す（表示位置を揃える）
- 実装は `.file-menu` を基本形とし、位置だけ上書きする（新しいメニュー実装を作らない）

### モーダル
- ヘッダー（14px / 600 / 下線）＋ 本文（`padding:14px 16px`）＋ 右上に `×`
- 背景クリック / `Esc` / `×` の3通りで閉じられること
- 大きい設定系は「左ナビ（172px）＋右コンテンツ」の2カラム

### 入力欄
- `surface2`（またはリスト内では `--bg`）の面 ＋ `border` 枠 ＋ `radius:6〜8px`
- フォーカスは **枠線の明色化のみ**（`--focus-border`）。OS のネイティブリングは無効化する
- キーボード操作のボタンは `:focus-visible` で `outline:2px solid var(--accent)`（common.css に集約済み）
- インライン編集（リネーム・ブックマーク編集）は枠を `--accent` にして編集中を示し、
  `Enter` 確定 / `Esc` キャンセルを必ず両方サポートする

### スライダー・シークバー
- トラック 5px（`surface2`・`radius:99px`）、つまみ 12px の円（`--accent`）
- シークバーはコントロール1段目に全幅で置く（シーク精度優先）
- マーカーは `pointer-events:none` の重ね層で描く。チャプター＝白 45%（2×9px）/
  ブックマーク＝`--warning`（2×12px）

### チャット
- 質問は右寄せの吹き出し（`radius:12px 12px 4px 12px`・`surface2`＋`border`）
- 回答は地の文（枠なし・背景なし・`line-height:1.7`）
- メタ情報（tok/sec 等）はアイコン付きの薄字チップ（枠なし・12px・`--text-dim`）
- 質問チップは入力欄の上に固定せず、会話履歴（スクロール領域）の末尾＝最後の回答の直後に
  右寄せで置く。回答生成中は隠し、回答完了後に再表示する
- Markdown 出力は `.qa-answer` 配下のスタイルに従う（見出し 1.0–1.3em・コードは `surface2`）

### 空状態
- 中央寄せ・`--text-dim`・12〜13px・`line-height:1.6`、大きめの薄いアイコン（34–48px）
- 何をすれば埋まるのかを1文で書く

### プログレス・ステータスログ
- バー高さ 6px（ログ内は 3px）、`radius:99px`、塗りは `--accent`
- ログ行は `8px 68px 1fr` のグリッド（ドット / 名前 / 本文）で列を揃える

### スクロールバー
- 幅 6px・トラック透明・つまみは `--border` の丸棒

## 10. レイアウト

- 画面は縦に「トップバー（42px）→ メイン行 → ステータスバー（28px）」
- メイン行は「ファイル一覧パネル（可変幅）｜プレイヤー ｜ 分析 ｜ チャット」の CSS Grid
  （`grid-template-areas: "player divider analysis qa"`）
- リサイザーは 1px の `--border` 線。当たり判定は `::before` で ±5px 広げ、ホバーで `--accent`
  にする（ダブルクリックで既定幅に戻す）
- **flex/grid の子には `min-height:0` / `min-width:0` を付ける。**
  付け忘れると内側の `overflow-y:auto` が効かずスクロールバーが消える
- ブレークポイントは 1100px / 760px / 520px の3つだけ。新しい値を増やさない

---

## 11. アクセシビリティ・安全性

- アイコンのみの操作には `title`、開閉するものには `aria-expanded` を付ける
- キーボード: モーダルは `Esc`、インライン編集は `Enter`/`Esc`、
  ボタンのフォーカスリングを消さない
- コントラスト: `--text-dim` を本文に使わない（補助情報だけ）。ティントの上の文字は同系の明色
- **モデル出力（動画内容由来＝信頼できないテキスト）を `innerHTML` に入れるときは必ず
  `renderMarkdown()`（内部で `sanitizeHtml()`）を通す。** 生の文字列連結で HTML を作らない

## 12. 実装ルール（どこに何を書くか）

| 置き場所 | 内容 |
|---|---|
| `frontend/css/common.css` | トークン・フォーカス規則・汎用部品（ボタン／バッジ／プログレス／スクロールバー等）。他アプリと共有できる粒度のものだけ |
| `frontend/pages/app.html` の `<style>` | このアプリ固有のレイアウトと部品 |
| インライン `style=` 属性 | **原則禁止。** 動的な値（幅・位置・進捗率・表示切替）だけに使う |

- クラス名はケバブケース、機能ブロックのプレフィックスを付ける
  （`file-` / `qa-` / `scene-` / `settings-` / `model-` / `ctrl-` …）
- 状態は修飾クラスで表す（`.active` / `.running` / `.done` / `.error` / `.open` /
  `.selected` / `.editing` / `.danger`）。新しい状態名を増やす前に既存を流用する
- `!important` は既存のメディアクエリの上書き以外で使わない
- 同じ見た目を2度書かない。3か所目が出たらクラスを切り出して `common.css` へ移す

## 13. 既知の未対応

- **ライトテーマ**: 未対応。トークン化は済んでいるので `data-theme` によるトークン差し替えで実現可能
- **インラインスタイルの残存**: 設定モーダルの `select`・ランタイム行・プロンプト編集 UI。
  `.field-select` / `.runtime-row` 等へ抽出して `common.css` に移すのが次の候補
- **文字サイズの逸脱**: ファイルツリーの 12.5 / 10.5 / 10px（§3）

（ロードマップとしての管理は [../plan/plan.md](../plan/plan.md) 側で行う）

## 14. UI 変更時のチェックリスト

UI を触ったら、コミット前に必ず全項目を確認する。

- [ ] 新しい色を生 HEX / 生 rgba で書いていない（トークンを使った。例外は §2-3 の3つだけ）
- [ ] 状態を面で表す箇所はティント形式（`--*-tint-bg` ＋ `--*-tint-border`）になっている
- [ ] 文字サイズが 11 / 12 / 13 / 14 のいずれか（表示系の例外を除く）
- [ ] 角丸が §4 の表のいずれか、境界線は `1px solid var(--border)`
- [ ] 余白が 2px グリッド、ペインのヘッダー高さは 56px に揃っている
- [ ] 影を足していない（浮く要素なら §6 の3種のどれかと完全一致）
- [ ] アイコンは Lucide（絵文字なし）、stroke-width と サイズが §7 の表どおり
- [ ] 動的生成後に `lucide.createIcons()` を呼んでいる
- [ ] アイコンのみのボタンに `title` がある
- [ ] トランジションは 0.15s 系、装飾目的のアニメーションを足していない
- [ ] 既存コンポーネント（`.btn-ghost` / `.file-menu` / バッジ / 状態ドット）を流用した。
      似て非なる部品を新設していない
- [ ] インライン `style=` を静的な見た目に使っていない
- [ ] スクロール領域の親に `min-height:0` / `min-width:0` がある
- [ ] モデル出力を表示する箇所は `renderMarkdown()` を通している
