# 動画レポート（1ページ Markdown＋画像）

動画の内容を「章立て＋スクリーンショット＋まとめ」の形で 1 ページにまとめ、
動画の隣の `{動画名}_report/` に書き出す機能。

## 確定方針

- **1 ページ構成が基本**（複数ページは将来のオプション）。`report.md` を正本にし、
  単一 HTML 書き出しは md から派生させる（正本を二重に持たない）
- 画像は **長辺 1280px の JPEG**（品質 88）。`images/` に置き、md からは相対パスで参照
- **似た画像を羅列しない**。候補の取り方・機械的な間引き・（第2段階で）VL による選定の
  3 段構えで重複を防ぐ
- 置き場所は `.cache/`（アプリ管理の中間物）ではなく、`_screenshot/` と同じ
  「ユーザー向け成果物」として動画の隣に置く。ファイル一覧からは除外し、
  リネーム・ごみ箱移動はサイドカーとして追随する

## 出力

```
video.mp4
└── video_report/
    ├── report.md      … 1 ページの Markdown（正本）
    ├── report.html    … 画像を base64 埋め込みした単一 HTML（md から派生。ダブルクリックでブラウザ表示）
    ├── report.json    … 章・画像・統計の構造（再生成・HTML 書き出し用）
    └── images/
        ├── ch01_1_00-00-26.318.jpg   … 章番号_連番_時刻
        └── bookmark_{id}_HH-MM-SS.mmm.jpg
```

`report.md` の構成: タイトル（動画名）／長さ・ジャンル・生成日時／タグ／概要（meta.summary・detail）／
目次（章へのアンカーリンク）／章ごとに「見出し・時間範囲・まとめ・画像（時刻キャプション）」／
末尾にブックマーク（時刻・タイトル・画像・コメント）。

## 第1段階（実装済み・2026-09-10）: LLM を使わない画像選定

`backend/report.py`

1. **候補の取り方**: ffmpeg の `select=gt(scene,0.30)` で「絵が切り替わった時刻」を候補にする
   （等間隔サンプリングだと同じ絵が並びやすい。スライド・画面共有に強い）。
   ハッシュ用なので幅 320px に縮小して 1 回だけ全編デコード。上限 1500 枚。
   候補が乏しい章（切り替わりが無い）には章の先頭＋中間を補う
2. **機械的な間引き**（レポート全体で、時間順に既採用の絵と比較）
   - 「同じ絵」: dHash（64bit）のハミング距離 ≤ 12 **または** 16×16 グレースケールの
     平均絶対差 ≤ 8 → 捨てる（講演者が少し動いただけの同一スライドは後者で拾える）
   - 「似た絵」: ハミング距離 ≤ 20 → 補欠。その章に他の候補が無いときだけ、
     既出から最も遠い 1 枚を使う（講演者アップの繰り返しを抑える）
   - 真っ黒・単色に近いフレーム（平均輝度 < 12・標準偏差 < 6）は捨てる
   - 章ごとに最大 3 枚を時間的に等間隔で選ぶ。全候補が落ちた章は先頭を 1 枚確保
3. **本番抽出**: 選ばれた時刻だけを入力シーク（`-ss`）で 1280px に抽出（並列 4）
4. **書き出し**: `report.md` / `report.json` に加え、`build_html()` で画像を data URI として
   埋め込んだ `report.html` を生成（12 分・26 枚で約 0.9MB）。VS Code のプレビューは
   「’」「：」を含むフォルダパスで画像を解決できなかったため、ビューワ非依存の HTML を
   第3段階から前倒しした

実測（Computex キーノート 12 分・19 章）: 候補 82 → 採用 26 枚、処理 1.4 秒。
残る課題: 同一章内の別背景の講演者ショット、ズーム違いの同一スライドは画素比較では
区別できない（→ 第2段階の VL 選定で扱う）。

### API

`POST /report/generate`（SSE）
```
{video_path, chapters:[{start_sec,title,summary}], meta:{genre,summary,detail,tags},
 bookmarks:[{id,time_sec,title,comment}], max_images_per_chapter=3, image_max_side=1280, hash_distance=12}
```
章の終了時刻はサーバー側で次章の開始から算出する（フロントの toc の `end_sec` は仮値のため使わない）。

リクエストには `use_llm`（既定 true）と `transcript`（SRT が無いときのフォールバック）も渡せる。

イベント: (`loading_model`) → `detecting_scenes` → `extracting {phase:"candidates"}` → `selecting {current,total,picked}`
→ (`generating {current,total,title}` ／ `report_warning {message}`) → `extracting {phase:"images",current,total}`
→ `writing` → `done {report_path,html_path,dir,chapters,images,stats}` ／ `canceled` ／ `error`

### フロント

分析パネルの操作行に「レポート」ボタン（`.btn-ghost`・Lucide `book-text`）。章立てがあるときだけ有効。
進捗はステータスバー（kind=`report`）、完了時にエクスプローラーで `report.html` を選択表示。

## 章立ての作り直し（2026-09-10・→ video-kinds.md）

分析のチャプターは映像主導で細切れになりやすいため、設定「レポート用に字幕から章立てを作り直す」
（既定 ON）が有効で VL を使うときは、`/report/generate` が先にシーン検出＋字幕から話題アウトラインを
作り、その章でレポートを組む。プレイヤーのチャプターは変えない。種類は `meta.video_kind` → 設定値。
Computex 12 分では 19 章 → 5 章になった。

## 第2段階（実装済み・2026-09-10）: VL による本文生成と画像選定

`backend/report.py` の `generate_chapter_texts()` ＋ `VideoReviewer.report_chapter()`

- 章ごとに、間引き後の候補フレーム（最大 6 枚・長辺 640px・時刻ラベル付き）と、その区間の
  字幕行（最大 1800 文字。長ければ等間隔に間引き）を VL モデルに渡し、json_schema で
  `{summary, points[], images[{time, caption}]}` を返させる。`time` は候補の時刻ラベルを
  そのまま返させ、サーバー側で最近傍の候補にスナップ（±2 秒超は無視）
- 字幕は `_report_transcript_rows()` が 日本語 SRT → 補正 SRT → 原文 SRT（cache 内 → 旧・横置き）の
  順で探し、無ければフロントから渡された `[m:ss] text` 形式の transcript を使う
- プロンプトで「スライド・図・製品・デモ画面など情報量の多いフレームを優先、話者だけのフレームは
  他に無いときだけ、似た画像は 1 枚に」と指示。1 章あたり上限は設定値（既定 3）・最低 1 枚
- 章単位で回すので分析の refine パスと同じくコンテキスト予算に収まる。章の生成に失敗したら
  `report_warning` を流して機械選定（第1段階）の結果で続行。トークン上限打ち切りも警告
- 本文は summary（2〜4 文）＋ points（箇条書き）。画像キャプションは「内容（時刻）」の形式
- 実測（Computex 12 分・19 章・Qwen3.8-27B Q4_K_M）: 116 秒（約 6 秒/章）・画像 21 枚。
  機械選定のみ（26 枚）より講演者ショットが減り、各章 1 枚のスライド中心になった

### 設定（設定 → 動画分析 → レポート）

- `report_use_llm`（既定 ON）: オフにすると第1段階のみ（本文はチャプターの説明をそのまま使う）
- `report_images_per_chapter`（1〜5・既定 3）

## 第3段階（前半・2026-09-10 実装）: アプリ内プレビュー

- チャプター／ブックマークと同じペインの「レポート」タブ。`POST /report/load` で report.json を読み、
  md ではなく構造から描画する（章タイトル・目次・画像に `data-start` を持たせてクリックでシーク。
  本文はモデル出力なので escHtml 経由。marked は使わない）
- 画像は `GET /report/image?video_path&name=images/...`（`images/` 外は 403・no-store）
- ツールバー「場所を開く」（report.html を選択表示）「再生成」。未生成時は「レポートを生成」ボタン。
  生成完了時はレポートタブを開く（エクスプローラーは開かない）
- 動画オープン時に data.json と独立して読み、クローズ時に空表示へ戻す
