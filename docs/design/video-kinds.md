# 動画の種類と話題主導の章立て（backend/outline.py）

動画分析のチャプターは従来、サンプリングしたフレームを VL モデルに見せて「絵が変わったところ」を
scenes として返させていた（映像主導）。プレゼン・対談のように話の切れ目で章を分けたい動画では
細切れ（20〜30 秒の章）・重複（「登壇」が 2 回）・描写的な章名（「サーバーラックの全景」）になりやすい。

2026-09-10 に「動画の種類」プリセットと、字幕主導の話題アウトライン生成を追加した。
動画分析（`/review/analyze`）とレポート（`/report/generate`）の両方が同じ実装を使う。

## プリセット（設定 → 動画分析 → 動画の種類。ui-settings `video_kind`）

| id | 表示名 | 基準 | 1 章の目安 | 章数 | 最短 | 章名の付け方 |
|---|---|---|---|---|---|---|
| auto | 自動 | 字幕あり→ presentation、なし→ footage | | | | |
| presentation | プレゼン・講演・解説 | 字幕＋場面変化をヒント | 120 秒 | 4〜18 | 45 秒 | 話題を表す名詞句（見た目の描写は禁止） |
| talk | 対談・インタビュー・配信 | 字幕のみ | 300 秒 | 3〜12 | 90 秒 | 話題（質問・テーマ）の名詞句 |
| tutorial | チュートリアル・画面操作 | 字幕＋場面変化をヒント | 120 秒 | 4〜20 | 45 秒 | 「〜する」「〜の設定」の手順形 |
| footage | 映像作品・Vlog・スポーツ | 映像（従来どおり） | | | | 場面の短いタイトル |

プリセットは内部的に 3 つのパラメータ（章分けの基準・粒度・章名の指示）に展開されるだけなので、
種類を増やしても実装は膨らまない。

## 話題アウトラインの生成（`generate_outline`）

- 入力: `[m:ss] text` 形式の字幕（全編を等間隔に間引いて最大 9000 文字）、動画の長さ、
  プリセット、場面変化の時刻（basis=both のときの境界ヒント。最大 80 件）
- VL モデルへフレーム無しのテキストのみ推論（`VideoReviewer.text_infer`）。json_schema で
  `{chapters:[{start, title, summary}]}` を返させる。12 分の動画で数秒〜十数秒
- 後処理（`normalize_chapters`）: 時刻順・先頭を 0 秒に・最短長未満の章は前の章へ統合・
  終了時刻は次章の開始から算出。`basis: "topic"` を付ける
- 字幕が 3 行未満・失敗 → `[]` を返し、呼び出し側は映像主導の章で続行（警告を SSE で通知）

## 動画分析への組み込み

1. coarse パス（フレーム＋字幕サンプル → summary / detail / tags / genre / scenes）は従来どおり
2. 種類の basis が topic/both で字幕があるとき、`outlining` イベントを流してアウトラインを生成し、
   映像主導の scenes を置き換える。refine パス（映像の細分化）は行わない
3. 結果に `video_kind`（解決後の id）と `chapter_basis`（topic / visual）を含め、フロントは
   data.json の `meta.video_kind` / `meta.chapter_basis` に保存する

実測（Computex キーノート 12 分・字幕あり・auto → presentation）: 映像主導では 19 章
（重複・描写的な章名）だったものが 6 章になり、章名は「Vera Rubin システムと AI ファクトリー」
「RTX Spark による PC の再発明」のような話題名になった。分析全体で 28 秒。

## レポートへの組み込み

設定「レポート用に字幕から章立てを作り直す」（`report_rebuild_chapters`・既定 ON）が有効で
VL を使うとき、`/report/generate` は先にシーン検出（境界ヒント兼、後段の画像候補にも再利用）→
アウトライン生成を行い、その章でレポートを作る。プレイヤーのチャプター（data.json の toc）は
変更しない。種類は `meta.video_kind`（分析時の値）→ 設定値の順で決める。
